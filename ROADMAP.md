# Hallow Places roadmap

## Done

| Version | What |
|---|---|
| 1.0 | **Server** (Node 20+, no npm packages, Docker, port 8091 on the NAS): OwnTracks HTTP mode at `/pub` (HTTP Basic, user name + a 256-bit random token per phone, only its SHA-256 stored, failed sign-ins limited per visitor; `location` and `transition` used, other `_type`s accepted and ignored; replies carry the family as OwnTracks friends (`card` + `location`, paused people never) and `setWaypoints` when the Places change). **Payload encryption**: OwnTracks `encryptionKey` = libsodium secretbox (XSalsa20-Poly1305) in pure JavaScript (`lib/secretbox.js`: Salsa20/20, HSalsa20, BigInt Poly1305), on by default per person; tested against the NaCl secretbox and core1 vectors, RFC 8439's Poly1305 vector and 300 random Node ChaCha20-Poly1305 tags, and cross-checked by hand against libsodium on the build PC; plain messages from an encrypting phone are dropped and flagged. **Storage**: `history/<person>/<YYYY-MM-DD>.jsonl` append-only, whole days deleted after the retention (default 30 days, hourly sweep), "delete my history" (day files, last position, geofence state, alert flags and feed items). **Auth**: scrypt (N=16384) passwords, admin password set with a one-time code from the log (or `ADMIN_PASSWORD`), HttpOnly SameSite=Strict sessions, `X-Hallow` header on every POST, strict CSP. **Phone setup**: QR code (own encoder, byte mode, level L, versions 1-40, ported from Hallow Remote and identical to it for 1-6, read back by an independent decoder in the tests), `owntracks:///config?inline=` link and a one-time `.otrc` download (30 minutes). **Map web app**: own slippy-map renderer (Web Mercator `<img>` tiles, fractional zoom, drag / pinch / wheel / double-click, SVG accuracy circles, Places and tracks), configurable tile URL and credit (OSM by default, referrer sent, no prefetch), light / dark, phone layout, day picker for tracks. **Alerts**: hysteresis (accuracy limit 100 m; arrive = 2 fixes inside or one fix with 2 x accuracy inside; leave = fixes past the exit radius max(1.5 r, r + 50 m) with the accuracy circle off the Place for 3 min, or one fix 300 m past it, never from one stray fix followed by silence; OwnTracks region events cross-checked), rules (arrive, leave, hasn't left by, hasn't arrived by, battery under, no update for, stationary at an unknown place), per-person quiet hours (feed only), de-duplication (episode flags + 15 min cool-down), delivery to the in-app feed, a Discord webhook and ntfy (write-only secrets, never logged). **Consent**: the Me page (what's shared, with whom, where alerts go, retention, encryption), pause that hides the person from everyone incl. the admin and drops what the phone sends, resume only by the person. **Tests**: 59 unit tests and an integration run (stand-in Discord / ntfy / tiles, a made-up day replayed by a fake OwnTracks phone, headless Edge at phone and desktop sizes in light and dark). NAS-DEPLOY.md and `scripts/deploy-nas.mjs`. |

## Later

| Idea | Why it isn't in 1.0 |
|---|---|
| **Live on the NAS** at `places.hallowservices.com` | Needs the NAS's sudo password for Docker and the Cloudflare tunnel / DNS steps - paused, like Hallow Assist's relay. Steps in NAS-DEPLOY.md. |
| **Circles** (who sees whom) | 1.0: everyone with a sign-in sees everyone who shares (and the Me page says so). Per-viewer circles need a sharing matrix and a clearer Me page. |
| **Hallow Remote** link and a **Hallow family pipe** | Remote could open the map, and a PC-side `HallowFamily.Places` pipe could raise alerts through Hub's `notify`. 1.0 is server + web only, on purpose. |
| **Web push** to the browser / PWA | Needs VAPID keys and the Web Push protocol (ECDH + AES-GCM, doable with node:crypto); Discord and ntfy cover phones for now. |
| **MQTT mode** | OwnTracks' other transport; HTTP mode is simpler behind a Cloudflare Tunnel. |
| **Import Places from the phones** | Phones can send their own regions (`waypoints`); 1.0 keeps Places admin-managed and pushes them to the phones. |
| **Per-place schedules** ("only on school days") for arrive / leave | Time rules already have weekdays; arrive / leave rules don't yet. |
| **Export** a day's track (GPX) | Small; not needed for 1.0. |
| **Offline map tiles** on the NAS | A tile cache or vector tiles would remove the dependency on OSM's servers; the tile URL is already configurable. |
